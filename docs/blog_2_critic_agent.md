# 博客 2 大纲：给 Agent 加一个「挑刺的审稿人」——Critic 与自纠错回环

> 定位：技术复盘，承接博客 1 的结尾（"下一步想懂『评估』"）。
> 核心叙事：LLM 会幻觉，怎么用「另一个 LLM」来抓幻觉？答案是——不靠 LLM 抓引用，
> 用两个不同厂商的 LLM 抓「夸大结论」。

---

## 一、问题：生成式 Agent 的天花板是「幻觉」

- 引子：V1.0 的 Summarizer 会"一本正经地编造引用 `[9]`，而实际只有 4 篇论文"。
- 定性：生成的 Agent 都会「自信地错」，关键不是让生成者更聪明，而是**加一个质疑者**。
- 引出：Critic Agent 的设计目标——不产出内容，只负责挑错。

## 二、Critic 的三道关（各防一类错）

### 2.1 确定性引用核查：不用 LLM 抓编造引用
- 代码：`re.findall(r"\[(\d+)\]", report)` + 计数比对 `len(sources)`。
- 为什么「不用 LLM」是关键：让 LLM 检查 LLM 的输出，等于让犯人自己审自己。
- 例子：4 篇文献出现 `[9]` → 必判 high 严重度，评分压到 ≤4.0。

### 2.2 两模型交叉验证：GPT 与 Claude 做「第二意见」
- 为什么用**不同厂商**：同一模型的偏见会「重复自己的错误」，换厂商才是真正独立判断。
- 合并规则：issues 取**并集**（任一模型揪出都算），评分取 **min**（两模型都高分才通过）。

### 2.3 事实核查：把结论与原文逐条比对
- prompt 设计：给 Critic 报告 + sources，让它判断「有没有原文没说的话」。

## 三、自纠错回环：把「挑错」接回「重写」

- mermaid 图：`summarize → critic →（score<6 且 ≤2 轮）→ summarize`。
- 关键点：`MAX_CRITIC_RETRIES=2` 防死循环——回环必须有界，否则 LLM 永远不满意。
- 类比：不是「无限返工」，是「最多改两遍，还不行就交付人工」。

## 四、一个反面教训：温度必须是 0

- Critic 用 `temperature=0.0`，核查要**确定可复现**，不能像创意写作那样随机。
- 对比：Planner 用 0.3（需要一点发散），Critic 用 0.0（要稳定）。

## 五、测试怎么测「会挑错的 Agent」

- mock 两个 LLM 返回固定 JSON；确定性引用核查直接测纯函数。
- 关键测试：`test_fabricated_citation_caps_score`——完美报告 + `[99]` 引用 → 分数 ≤4.0。

## 六、心得
- 生成与质检**分离**、**异构模型**、**确定性兜底**，是抑制幻觉的三板斧。
