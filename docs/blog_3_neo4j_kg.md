# 博客 3 大纲：用 LLM + Neo4j 给生物医学文献建知识图谱

> 定位：技术复盘。核心叙事：生物医学是知识图谱的黄金场景（药物-靶点-疾病天然是图），
> 难点不在「怎么建图」，而在「怎么让 LLM 抽取可靠、写入幂等、离数据库也能测」。

---

## 一、为什么生物医学适合知识图谱

- 药物-靶点-疾病天然是**图结构**（不是表格），关系推理是刚需。
- 例子：CAR-T → 靶向 CD19 → 治疗 B 细胞白血病，链条一目了然。
- 引出：从「检索文献」升级到「组织知识」。

## 二、抽取：LLM 主抽取 + 词典兜底

### 2.1 实体与关系的限定
- 实体：drug / target / disease / gene；关系：TREATS / TARGETS / ASSOCIATED_WITH / ENCODES / IMPLICATED_IN。
- 为什么**限定**：不限定，LLM 会抽出一堆无意义关系（"论文提到 X"）。

### 2.2 词典兜底：LLM 抽不到的用规则补
- 预置药物/靶点/疾病词典，规则匹配共现实体。
- 关键约束：只对**同一文本中同时出现**的实体对生成三元组，避免臆造。

### 2.3 去重合并
- 按 `(head, relation, tail)` 三元组键去重。

## 三、写入：为什么用 MERGE 而不是 CREATE

- `CREATE` 重复写入会造出重复节点，图谱变成「一团乱麻」。
- `MERGE` 先查重再建节点，幂等——重复跑结果不变。
- Cypher 示例：`MERGE (a:Drug {name:'CAR-T'}) MERGE (b:Disease {name:'leukemia'}) MERGE (a)-[:TREATS]->(b)`。

## 四、工程解耦：Cypher 与连接分离

- `build_cypher` 是**纯函数**——不连数据库也能测、也能预览。
- `write_triples` 才真正连 Neo4j（驱动延迟导入，未装/未启动不阻塞抽取）。
- 好处：单元测试零依赖，CI 不用跑真实 Neo4j。

## 五、坑与心得
- 关系名要清洗（`re.sub(r"[^A-Z_]", "", relation.upper())`），LLM 会返回带空格的怪关系。
- 节点标签首字母大写 + 只留字母数字。
